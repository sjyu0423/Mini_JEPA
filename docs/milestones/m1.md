# Milestone 1: Small temporal JEPA

## Scope

M1 adds a genuine JEPA-style latent prediction experiment in PyTorch. Four rendered frames are
used to predict the representation of a future rendered frame. Positions, velocities, and
collision labels remain outside the PyTorch dataset interface and are never used as targets.
There is no decoder or pixel reconstruction objective.

## Architecture and tensor shapes

The model has 203,584 trainable parameters and 349,312 total parameters. The 145,728-parameter
target encoder is frozen and updated only through EMA.

1. A shared online frame encoder maps each `(batch, 1, 64, 64)` frame through three stride-2 CNN
   blocks (channels 16, 32, 32), a spatial projection, and LayerNorm to a 64-dimensional vector.
2. The context encoder applies that same online frame encoder independently to four observations,
   concatenates the four vectors to `(batch, 256)`, and uses a `256 -> 128 -> 64` temporal MLP.
3. The target encoder is an architecturally identical EMA copy of the online frame encoder. It
   processes only the actual future frame and is always evaluated without gradients.
4. The predictor is a `64 -> 128 -> 64` MLP that maps context embeddings into target-embedding
   space.

Using a shared single-frame encoder resolves the incompatible four-frame context and one-frame
target input channels. Only the context side needs the separate temporal aggregator. The dataset
selects the target index from the configured prediction horizon, so the same architecture supports
different horizons without privileged motion labels.

## Objective and collapse safeguards

The prediction term is mean cosine distance between the predictor output and the detached EMA
target embedding. A variance-floor penalty is applied to trainable context and prediction
embeddings across each batch:

```text
loss = (1 - cosine(prediction, stop_gradient(target)))
       + 0.1 * variance_floor(context, prediction; minimum_std=0.1)
```

Target, context, and prediction variance are logged separately. This does not prove semantic or
physical understanding; it only makes total constant-vector collapse visible and directly
discourages collapse on the trainable branches.

## Dataset and training configuration

The experiment used M0-generated trajectory splits:

- generation seed: 2026
- trajectories: 256 train, 64 validation, 32 held-out test
- frames per trajectory: 32
- observed frames: 4
- prediction horizon: 1
- sliding windows: 7,168 train and 1,792 validation
- input tensor: `(batch, 4, 1, 64, 64)`, float32 in `[0, 1]`
- target tensor: `(batch, 1, 64, 64)`, float32 in `[0, 1]`

Training used AdamW, batch size 64, learning rate `3e-4`, weight decay `1e-4`, EMA decay `0.99`,
five epochs, and seed 2026. Apple MPS was selected automatically. The measured training duration
was 12.80 seconds, excluding dataset generation and tests.

The best validation checkpoint is epoch 5. Target and context representations retain substantial
cross-sample variance, so there is no sign of total constant-vector collapse in this run. Predictor
variance is much smaller and declined slightly; this is a reason for continued monitoring and
downstream evaluation, not evidence of successful motion semantics. A decreasing latent loss by
itself does not establish that the model learned physics or accurate position prediction.

The tiny smoke run used 8/2/1 trajectories and a 32-dimensional model. Its checkpoint was resumed

checkpoint restoration tests.

## EMA and checkpoint behavior

After each optimizer step, every compatible target parameter is updated as
`target = decay * target + (1 - decay) * online`. Target parameters have `requires_grad=False`,
the target module remains in evaluation mode, and its forward pass is under `no_grad`.

Both best-validation and latest checkpoints include online, target, predictor, optimizer, epoch,
best loss, full metric history, and model/training configuration. Loading restores model and
optimizer state and reasserts target freezing. Resume continues at the following epoch.

## Technical limitations and M2 preparation

- There is no quantitative probe of what the representation contains yet. M2 must evaluate it
  without treating the M1 latent loss as proof of motion understanding.
- Prediction variance is lower than context and target variance and warrants monitoring.
- Resume restores model and optimizer state but not exact DataLoader/RNG position, so it is
  functional rather than bitwise-identical to an uninterrupted run.
- The experiment covers one prediction horizon and one short hyperparameter configuration.
- The test split is generated and held out; it is intentionally not used for M1 model selection.

M2 can load `best.pt`, freeze or evaluate the learned representations, and add the explicitly
deferred position probes and conventional baselines. Those components are not implemented in M1.
