# Milestone 4: Interactive prediction demo

## Purpose

M4 is a local visualization of existing frozen research artifacts. It does not train, fine-tune,
or alter any model. Four rendered observations are passed to a JEPA context encoder and predictor;
the matching frozen downstream probe converts the predicted embedding into a next-frame position.

The application avoids claiming that latent similarity or a low position error proves physical
understanding. It also labels the constant-velocity baseline as privileged because that baseline
receives measured positions while JEPA receives images only.

## Architecture

The demo has no new runtime dependency beyond the existing project:

1. `DemoEngine` loads M1, M3, and both probes once, verifies their embedding/output dimensions,
   freezes the networks, and keeps them cached on MPS or CPU.
2. Existing event-driven physics and Pillow rendering generate deterministic 180-frame scenarios.
3. Contexts are built explicitly as frames `t-4` through `t-1`; frame `t` is never passed to a
   predictor. All contexts are batch-inferred for responsive playback.
4. A Python `ThreadingHTTPServer` bound to loopback serves static HTML/CSS/JavaScript and two JSON
   endpoints. There is no cloud service, telemetry, or publication.
5. The browser draws the arena with Canvas, reveals actual state only as playback reaches a frame,
   and computes/display errors for predictions that have become realized.

The API precomputes an entire deterministic trajectory for smooth playback. Future truth is
resident in the browser response, but the interface does not display it early and, critically, no
future image or state enters model inference. Automated tests verify context slicing and invariance
to changes in the target frame.

## Setup and launch

From the repository root:

```bash
uv sync --locked
uv run mini-jepa-demo --host 127.0.0.1 --port 8877 --device auto
```

Then open `http://127.0.0.1:8877`. `auto` selects Apple MPS when available and otherwise uses CPU.
Port 8877 is the default because port 8765 was already occupied during local acceptance testing.

The interface provides:

- play, pause, single-step, reset, and 0.25×–3× speed;
- ordinary, near-wall, high-speed, and multiple-bounce deterministic scenarios;
- M1, M3, and constant-velocity model selection;
- current actual, next prediction, and realized-prediction overlays;
- trajectory trails, collision highlighting, current frame, coordinates, and error history;
- explicit pending target labels so the next actual coordinate is not shown early;
- concise descriptions of image-only JEPA input and downstream probe supervision.

## Measured latency

Acceptance used Apple MPS with batches of 176 aligned contexts from a 180-frame trajectory.
Checkpoints loaded in 643 ms. Five consecutive scenario runs were recorded in
`artifacts/m4/latency.json`.

- The first benchmarked run included MPS graph/shape warm-up: 1.219 ms per M1 prediction and
  0.136 ms per M3 prediction.
- The following four steady-state runs averaged approximately **0.031 ms per prediction** for both
  M1 and M3 when amortized across the batch.
- The five-run means, including the warm-up outlier, were 0.268 ms for M1 and 0.052 ms for M3.

These are batched, amortized inference measurements, not single-request latency. Scenario
generation, rendering, JSON serialization, and network transfer are excluded from the reported
model timing.

## Testing and acceptance

The complete M0–M4 suite contains 41 passing tests. M4 coverage includes:

- real M1/M3 checkpoint and matching probe loading;
- frozen parameter state and probe dimensional compatibility;
- finite `(samples, 2)` output from all three predictors;
- exact four-observation/one-target alignment;
- target-frame exclusion and future-frame mutation invariance;
- deterministic scenario playback;
- renderer-scale pixel error calculations;
- scenario/model selection and aligned payload structure.

Ruff lint, Ruff formatting, locked dependency synchronization, HTTP readiness, API inference, and
desktop/narrow browser rendering also passed.

## Known limitations

- The demo visualizes independently predicted horizon-1 steps. It is not a recursive rollout and
  must not be interpreted as validated multi-step forecasting.
- Full trajectory truth is preloaded into the local browser for animation, though it is hidden
  until its frame and never enters the model.
- Coordinate probes can occasionally predict slightly outside the arena because their outputs are
  not physically constrained.
- Batched precomputation makes playback smooth but differs from strict per-frame online latency.
- The near-wall scenario is fixed apart from seed-independent custom initial state; reset is
  intentionally deterministic.
- The application is a single-user localhost research interface with no authentication or public
  hosting and should remain bound to `127.0.0.1`.
